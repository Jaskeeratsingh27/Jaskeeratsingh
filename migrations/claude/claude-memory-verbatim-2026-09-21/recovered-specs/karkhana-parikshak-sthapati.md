# Karkhana / Parikshak / Sthapati — recovered project trio

Evidence level: verbatim Claude memory says all three were built and delivered as Claude Project ZIPs containing setup/instructions/knowledge files. Those ZIPs are absent from the migration archives.

## Karkhana

Historical purpose: workshop for building agents on the user's own runtime stack. The production artifact was a Hermes `SKILL.md`; Hermes was intended to be the production runtime/orchestrator, while Claude was used to author/improve skills.

## Parikshak

Historical purpose: audit agentic systems using Lean Six Sigma/DMAIC-style analysis. Memory says its audit doctrine was grounded in the MAST failure taxonomy and the OWASP Top 10 for Agentic Applications 2026. Those external frameworks are time-sensitive and must be re-verified before any rebuild.

## Sthapati

Historical purpose: build Claude Projects. Memory says the delivered project included its own 16-test pack.

## Cross-testing intent

The intended quality loop was to use the projects on one another: Sthapati could generate/test project packs for the others, while Parikshak audited all three.

## Migration treatment

Record these as **shipped-but-source-missing**, not as recovered executables. Do not fabricate their original instructions from memory prose. If the authoritative ZIPs appear in a later source, ingest and reconcile them against this record.
