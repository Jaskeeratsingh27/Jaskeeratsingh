# V1.3 primary-source notes

Verified: 2026-09-26

## GitHub webhook authentication

Primary source: GitHub Docs — Validating webhook deliveries  
https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries

Used contract:
- configure a high-entropy webhook secret,
- validate the original payload with HMAC-SHA256,
- read the signature from X-Hub-Signature-256,
- use constant-time comparison,
- never hardcode/store the secret in source control.

## GitHub delivery identity

Primary source: GitHub webhook event documentation  
https://docs.github.com/en/webhooks/webhook-events-and-payloads

Used contract:
- X-GitHub-Delivery is the delivery identifier.

## Jira Cloud webhook authentication/reliability

Primary source: Atlassian Developer — Jira Cloud webhooks  
https://developer.atlassian.com/cloud/jira/software/webhooks/

Used contract:
- secure HTTPS callback endpoints,
- optional webhook secret for HMAC validation,
- X-Hub-Signature carries method=signature,
- X-Atlassian-Webhook-Identifier remains stable across retries,
- duplicate delivery is therefore expected and must be idempotent,
- webhooks avoid periodic polling.

## Design consequence

Provider webhook identifiers are namespaced by source before persistence. The event
store additionally records a SHA-256 body hash so the same identifier with different
content is treated as a collision/tampering condition rather than a benign retry.
