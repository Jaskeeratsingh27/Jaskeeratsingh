## GitHub App authentication

GitHub Docs:
- https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/about-authentication-with-a-github-app
- https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app

Design consequences:
- unattended automation should authenticate as a GitHub App installation,
- the app JWT is used to request an installation token,
- installation tokens are short-lived and must not be treated as fixed-format permanent credentials.

## Jira Cloud external integration authentication

Atlassian:
- https://developer.atlassian.com/cloud/jira/platform/rest/v3/intro
- https://developer.atlassian.com/cloud/jira/service-desk/oauth-2-authorization-code-grants-3lo-for-apps/
- https://developer.atlassian.com/cloud/oauth/getting-started/refresh-tokens/

Design consequences:
- external integrations use OAuth 2.0 authorization-code grants (3LO),
- offline access supplies refresh tokens,
- refresh tokens rotate and the replacement token must overwrite the previous token,
- scopes and underlying user permissions both constrain access.

## Secret storage

Atlassian cloud-app security requirements:
- https://developer.atlassian.com/platform/marketplace/security-requirements/

Design consequence:
OAuth secrets must not be stored in source code/logs and production storage must protect them at rest.
