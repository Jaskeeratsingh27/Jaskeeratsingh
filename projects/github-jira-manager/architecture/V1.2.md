# V1.2 Architecture

## Objective

Convert the four conceptual specialists into enforceable contracts and introduce deterministic GitHub→Jira reconciliation without allowing external events to bypass QA or human approval.

## Runtime flow

```
Human
  |
Orchestrator
  |-- Project Manager -> Jira
  |-- Software Engineer -> GitHub
  '-- QA Validator -> CI/tests
               |
        Reconciliation Engine
               |
        desired Jira state
```

## Separation of concerns

- Model reasoning may decide *what should be attempted*.
- Agent contracts decide *which role may attempt it*.
- Policy decides *whether the operation class is allowed*.
- Reconciliation decides *what Jira state evidence permits*.
- Jira/GitHub APIs perform the actual side effect.
- Human approval remains authoritative for merge/release/production/destructive actions.

## Reconciliation rules

- PR opened → In Progress.
- CI failed → Blocked.
- CI passed → In Progress; QA remains mandatory.
- PR ready + CI + QA → In Review.
- PR merged + CI + QA + explicit human approval → Done.
- Missing evidence → no forward transition.

## Delivery limitation

V1.2 contains the reconciliation **decision engine and contracts**. Always-on webhook ingestion is still a later deployment concern; in the current ChatGPT workflow, connector events are read and fed through the same deterministic rules interactively.
