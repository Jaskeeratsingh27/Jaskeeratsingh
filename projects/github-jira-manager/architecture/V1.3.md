# V1.3 Architecture — durable runtime and webhook boundary

## Goal

V1.3 makes event receipt and reconciliation durable across process/chat restarts.

```
GitHub/Jira webhook
        |
        v
signature verification
        |
        v
persistent inbound event
        |
        v
reconciliation decision
        |
        v
durable outbox
        |
        v
authenticated side-effect worker
        |
        v
Jira/GitHub API
```

## Reliability rule

**Persist before acting.** A webhook is never acknowledged conceptually as processed
only in memory. Delivery identity and payload hash are stored first. Duplicate delivery
IDs with the same content are no-ops; a reused ID with different content is rejected.

## Outbox rule

Reconciliation does not directly mutate Jira. It writes deterministic operation IDs
to an outbox. An external worker performs those operations and marks them complete.
If the process crashes, pending/failed outbox rows remain replayable.

## Security

GitHub deliveries require the SHA-256 webhook signature. Jira deliveries require the
configured HMAC signature. Secrets are runtime configuration only and are never stored
in the repository or SQLite event records.

## Current deployment boundary

The receiver/runtime is deployment-ready and framework agnostic. True unattended
Jira/GitHub writes require a deployed worker with service credentials/OAuth. ChatGPT
connectors are interactive credentials and are not embedded into this runtime.

## Storage choice

SQLite is the V1.3 deterministic reference implementation because it is dependency
free and allows crash/restart tests in CI. The production target remains Postgres;
the schema and outbox boundary are intentionally portable.
